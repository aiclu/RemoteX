# Fluent 标签高亮残留修复

## 原因与改动

侧栏将按钮放在 ListBoxItem 中。原先容器沿用 WPF 默认选中背景，按钮另有悬停／焦点状态；列表选中项和集合当前项并不是实际的标签筛选条件，因而会出现旧项仍有底色、新项又有焦点框的现象。

- 仅为 Fluent 标签容器使用无选中色的 ContentPresenter 模板，取消与集合当前项同步；保留单个虚拟化列表。
- 标签按钮的单标签选中背景、边框和字重绑定实际 `SelectedTabName`，复用已有相等比较转换器。
- 点击另一标签、返回全部连接或筛选切到多标签／排除组合时，旧单标签高亮自动撤销。多标签与排除条件继续由原有筛选条呈现，不把焦点当成筛选条件。
- 保留按钮键盘焦点、悬停、禁用状态，以及固定排序、图钉、右键命令、Ctrl／Alt 行为；未改连接筛选逻辑。

## 验证

- 完整 C# 测试 94 项通过。新增测试使用实际侧栏模板，故意保留旧列表选中项／当前项，依次切换 hp、personal、全部连接、多标签状态和 hp，验证只有当前单标签有背景与字重标记。
- 明暗隔离渲染保留旧列表选择 ordinary，但筛选 pinned；目视确认旧选择无底色、当前筛选有标记。仍检查屏外标签未生成容器。
- Debug 构建成功（现有 120 条警告，0 错误）；`Ui/bin/TagHighlightTest` 包含 RemoteX.exe 和 ssh_rust.dll。
- 上述状态绑定测试及隔离渲染不等同于实机点击／键盘和 DPI 验收，用户仍需确认实际连续点击效果。

版本保持 2.0.1，不提交、不推送、不发布。
